# UrbanShield AI — PRD

## Original problem statement
PART 22: POWER MONITORING & SMART AC ENERGY MANAGEMENT — Integrate a complete Power Monitoring module into the existing UrbanShield AI website (React + FastAPI), Chennai buildings/zones only, clearly distinguishing real IoT sensor readings from SIMULATED demo data. Sections: 1 Power Monitoring Dashboard, 2 Chennai AC Monitoring (10 zones), 3 AC Overload Detection (configurable 70/85/100 bands, no fault claims), 4 Abnormal Consumption Detection (rule-based), 5 What-If Power Simulation (with RESET TO BASELINE, temperature not affecting demand without documented assumption, baseline preserved), 6 Power Monitoring Map, 7 Smart Energy Recommendations (explained, no automatic control), 8 Intervention Integration with Climate Digital Twin scenarios, 9 API (/api/power/overview, zones, buildings, alerts, history, simulate, recommendations), 10 sample CSV data/sample/chennai_power_monitoring.csv labelled SIMULATED + future MQTT support, 11 testing, 12 pipeline Heat Monitoring → Heat Risk → AC Power → Overload → What-If → Recommendations → Emergency Priority.

## Architecture
- Workspace had NO existing UrbanShield code: built a minimal shell (pipeline nav) + full /power page; Heat Monitoring, Heat Risk, Emergency Priority routes are placeholders.
- Backend: `power_engine.py` (pure formulas, CSV loader/validator, snapshots, rules, simulation, scenarios, recommendations), `power_routes.py` (APIRouter /api/power), Mongo collections `power_settings` (thresholds/tariff) and `power_sensor_readings` (IoT ingestion).
- Data: `/app/data/sample/chennai_power_monitoring.csv` generated by `/app/scripts/generate_power_data.py` (30 buildings × 168 h, 3 intentionally invalid rows incl. one Bengaluru row, one building without coordinates).
- Frontend: React + react-leaflet (OSM tiles, dark filter) + recharts; components in `src/components/power/`.

## Implemented (2026-10-31)
